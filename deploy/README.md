# Chạy bản integration

**SQL Server.** Dùng tài khoản triển khai riêng có quyền đổi schema. Tài khoản API chỉ cần quyền đọc, ghi và chạy các procedure nghiệp vụ trong database gara. Không cấp quyền quản trị máy chủ cho API.

- Database mới: chạy `./backend/database/Update-GarageDatabase.ps1 -Server <server> -Database <db> -Create` dưới danh tính Windows của người triển khai. Không nạp khách, tài khoản hay giao dịch mẫu.
- Database đã có lịch sử: bỏ `-Create`. Script kiểm tra tên file, thứ tự và SHA-256 trước khi chạy phần còn thiếu. Giữ nguyên các file V002, V003 và V004 trùng số.
- Lần đầu tiếp quản database cũ: sao lưu, đối chiếu script cuối đã áp dụng với hồ sơ vận hành. Ví dụ **chỉ khi đúng là V011**: thêm `-BaselineThrough migrations/V011__customer_contact_messages.sql`. Script kiểm tra dấu hiệu schema trước khi ghi nhận. Lần sau bỏ tham số này. Không đoán baseline khi hồ sơ không rõ. Dùng `-TrustServerCertificate` chỉ với SQL Server phát triển cục bộ.

**Sao lưu và khôi phục.** Tạm ngừng ghi khi chuyển phiên bản. Tạo file mới bằng `BACKUP DATABASE [ten_db] TO DISK=N'<duong_dan_moi>.bak' WITH COPY_ONLY, CHECKSUM` rồi chạy `RESTORE VERIFYONLY FROM DISK=N'<file>.bak' WITH CHECKSUM`. Đường dẫn ở **máy SQL Server**. Bảo vệ bản sao vì có chứng từ khách hàng. Định kỳ đọc `RESTORE FILELISTONLY`, khôi phục thử sang **tên database mới**, dùng `WITH MOVE` cho từng file sang đường dẫn chưa tồn tại. Chạy `DBCC CHECKDB`, đối chiếu số dư hóa đơn và số lượng giao dịch trước khi công nhận bản sao. Không dùng `WITH REPLACE`. Khi cần quay lui, giữ database hiện tại, phục hồi sang database riêng và đối chiếu các giao dịch phát sinh trước khi đổi kết nối.

**API và Web.** Dùng Java 21, Node 22.12+ và bản SQL Server có chứng chỉ tin cậy. Trong `backend` chạy `./mvnw clean verify`; trong `frontend` chạy `npm ci`, `npx tsc --noEmit`, `npm run build`. Đặt thư mục `frontend/dist` và JAR ở thư mục ngoài repository. Chạy JAR dưới tài khoản dịch vụ với `SPRING_PROFILES_ACTIVE=prod`, `DB_URL` (JDBC SQL Server, `encrypt=true;trustServerCertificate=false`), `DB_USERNAME`, `DB_PASSWORD`, `CORS_ALLOWED_ORIGINS` (origin HTTPS của Web) và `JWT_SECRET` (khóa ngẫu nhiên ít nhất 32 byte). Truyền secret từ môi trường bảo mật; không đưa vào bundle React. API mặc định nghe tại 127.0.0.1:8080. Không chép file .env phát triển vào thư mục chạy.

Trên database mới, khởi động **một** tiến trình với `BOOTSTRAP_ADMIN_ENABLED=true`, `BOOTSTRAP_ADMIN_USERNAME`, `BOOTSTRAP_ADMIN_PASSWORD`, `BOOTSTRAP_ADMIN_FULL_NAME`. Khi đã có quản trị viên, tắt bootstrap, gỡ biến mật khẩu và khởi động lại. Quản trị viên tạo tài khoản nghiệp vụ; quản lý cấu hình khung giờ, danh mục và tài khoản nhận tiền trước khi nhận lịch.

Điền `GARAGE_DOMAIN`, `GARAGE_WEB_ROOT` rồi chạy `caddy validate --config deploy/Caddyfile --adapter caddyfile` và chạy Caddy trên máy chủ đã cấp DNS, cổng 80/443 và quyền cấp chứng chỉ. Web gọi API cùng origin. Kiểm tra `GET /api/health/ready` trả 200, Swagger production bị tắt, đăng nhập và tải lại trang báo giá trực tiếp. Chạy API/proxy bằng dịch vụ hệ điều hành có tự khởi động lại. Mobile dùng `flutter build apk --release --dart-define=API_BASE_URL=https://<domain>/api`. Kiểm tra trên điện thoại có mạng khác với máy chủ trước khi bàn giao.

**Cập nhật bản chạy.** Giữ JAR và thư mục Web của phiên bản trước. Sau khi sao lưu, chạy migration của phiên bản mới, khởi động JAR mới rồi thay thư mục Web khi readiness đạt. Theo dõi log dịch vụ ở mức INFO và mã HTTP 5xx. Giới hạn quyền đọc và thời gian giữ log. Không ghi header Authorization, nội dung chứng từ hoặc mật khẩu vào log proxy. Nếu readiness không đạt, giữ Web cũ và kiểm tra giao dịch trước khi quay lui.

**Kiểm thử thật.** GitHub Actions chạy build/unit độc lập với database gara. Job SQL chỉ chạy thủ công từ nhánh integration trên runner Windows gắn nhãn `garage-sql-verification`, đã cài Java 21, có database `QuanLyGaraOTo_Verify_YYYYMMDD` đã nâng cấp và secrets của environment `garage-verification`. Dùng dữ liệu, tài khoản và khóa riêng cho kiểm thử. Với Chrome/Flutter tại máy phát triển: chạy API kiểm thử tại 8088, cho phép origin `http://127.0.0.1:5188`. Đặt `GARAGE_VERIFY_CREDENTIALS` đến JSON riêng (database, manager/customer mỗi tài khoản có username/password) và `GARAGE_VERIFY_SHARE` đến file tạm để truyền mã báo giá, không chứa token. Chạy `npx playwright test -c playwright.live.config.ts insurance-live.spec.ts` trong frontend, rồi `flutter test test/insurance_sql_live_test.dart --dart-define=API_BASE_URL=http://127.0.0.1:8088/api` trong mobile. Kịch bản Web để lại hồ sơ trong database kiểm thử để Flutter đối chiếu.
